# Audience, goals and scope

## Purpose

Turn public technical work into an understandable personal portfolio, with deeper self-service exploration.

## Audience hypotheses — confirm before final copy

Potential collaborators and employers need a concise explanation of capabilities. Developers evaluating a tool need its purpose, docs, installation and maintenance status. Readers need clear technical articles. These are hypotheses, not confirmed user personas.

## Requirements

- PROD-001: The homepage answers who the author is, what they do and who benefits.
- PROD-002: Visitors can explore repos, projects, packages and docs through cards and Pagefind.
- PROD-003: Curated work provides problem, contribution and outcome rather than metrics alone.
- PROD-004: Public browse coverage and data freshness are disclosed.
- PROD-005: The site supports a GitHub-compatible profile README and a blog.

## Non-goals for the first release

A complete GitHub client; editing issues; authenticated visitor accounts; private repository access; live commit feeds; mirroring all code; indexing every external docs site by default.

## Success checks

A first-time visitor can explain the author's focus after reading the hero. A developer can find a relevant tool and reach its docs. A filtered catalog link is shareable. No invented credentials, outcomes or employment claims appear.
